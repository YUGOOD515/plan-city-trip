# 怎么排方案

## 三套方案

| 方案 | 定位 | 怎么排 |
| --- | --- | --- |
| A 经典 | 第一次来的人 | 攻略提及最多的地点（`mentions` 前 8–10 个）串成顺路的线 |
| B 主题 | 按用户偏好 | 用 `interests` / `note` 定主题（美食、历史、海边、拍照…）；没有偏好就选攻略里第二大类玩法（如大连的旅顺历史线） |
| C 省钱 | 预算敏感 | 免费景点 + 公共交通 + 便宜住宿 + 便宜的大交通（夜车、早班机）；要明显比 A 便宜 |

- 用户设了 `pace`（轻松 / 适中 / 较累）时三套都按这个强度；「三种都看看」时 A 适中、B 较累或适中、C 轻松。
- 用户的 `note` 是硬约束（如「周六晚上要看演出」「18:00 前到学校」），三套都要满足；满足不了就在 `tips` 里说明。
- 有 `budget` 时，至少 A 或 C 要在预算内；超了的方案在 `cost_notes` 写超多少。

## 每天怎么排

- 强度：轻松每天 3–4 个点，适中 4–5 个，较累 5–6 个；每个点写建议到达时间。
- 顺路：一天的点在同一片区，不来回横穿城市；景区开放时间、闭馆日（多数博物馆周一闭馆）要避开。
- 第一天：从到达时间开始排，先放行李（酒店在站点附近时不单列）；最后一天：留足去车站 / 机场的时间（高铁前 1 小时、飞机前 2 小时到）。
- 交通：步行 ≤ 2 km；2–8 km 打车或地铁；用户 `transport=自驾` 时市内用 `car`。
- 天气：有雨的那天把室内项目（博物馆、商场、海洋馆）挪过去，在 `tips` 里说。

## 人均怎么算

`cost.<人数>` 每项都是**人均**、人民币整数，不含购物：

| 分项 | 算法 |
| --- | --- |
| 往返交通 | 去程 + 回程单人票价（二等座 / 经济舱含税） |
| 住宿 | 酒店总价 ÷ 人数（按 `room_size` 人一间，人数为奇数时多开一间） |
| 当地交通 | 打车按 2.5–3 元 / km ÷ 同车人数（4 人一车）+ 地铁公交 |
| 门票项目 | 所有收费景点、演出、游船 |
| 餐饮 | 早餐 30、午晚各 60–120 × 天数，按城市消费调整；攻略里提到的必吃店按人均价 |

`cost_notes` 写清楚每一项的依据和来源（「12306 10/20 查询」「携程 2 晚 ¥900 / 间」「估算」）。

## 避坑怎么写

- 只写攻略里**多个视频**提到或有具体细节的；写成能照做的一句话（「老虎滩门票在官方小程序买比现场便宜 20 元」）。
- 不写泛泛的话（「注意安全」「提前规划」）。
- 和方案相关的坑放进该方案的 `tips`，通用的放顶层 `pits`。

## 价格

- 有网页搜索 / 浏览工具时：查 12306 或航司官网、携程 / 飞猪 / 美团酒店，记下查询日期写进 `checked_at`，来源写进 `sources`。
- 没有时：按常识估，`note` / `cost_notes` 里标「估算」，不要编具体车次号和酒店名（酒店可以写「中山广场附近四星，约 ¥450 / 晚」）。
